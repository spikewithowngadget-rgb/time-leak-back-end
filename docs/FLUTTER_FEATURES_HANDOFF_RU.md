# TimeLeak: передача новых функций Flutter-разработчику

Backend сохраняет `/api/v1`, авторизацию и существующие поля. Полный контракт:
`GET /swagger.json`, интерфейс: `GET /swagger`. Версия OpenAPI — **1.4.0**.
Ниже — изменения; остальные методы описаны в `FLUTTER_API_GUIDE_RU.md`.

## Поля заметки

| Поле | Запрос | Ответ / поведение |
| --- | --- | --- |
| `title` | JSON или multipart, необязательно | Текст до 200 символов; trim и удаление HTML. `null`/пусто = `note_type · YYYY-MM-DD`. В ответе всегда строка. |
| `title_audio` | Только multipart: один файл | Отдельное аудио до 2 MiB и 30 сек; m4a/aac/mp3/ogg. Не входит в `files`, `file_count` и `file_type`. |
| `title_audio_url` | Клиент не задаёт | URL аудио или `null`. Текст и аудио могут присутствовать одновременно. |
| `lifecycle` | `one_time` (по умолчанию) / `recurring` | Не меняет `note_type`. |
| `recurrence_rule` | Для recurring обязательно | Только `FREQ=YEARLY`, `FREQ=MONTHLY`, `FREQ=WEEKLY`; для one_time — `null`. |
| `is_completed` | Клиент не задаёт | Автоматически выставляется для прошедших one_time. История не удаляется. |
| `occurrences` | Клиент не задаёт | Массив виртуальных дат в диапазоне; без диапазона и для one_time — `[]`. |

В `PUT` **отсутствующее поле сохраняет значение**. Для сброса title передайте
`null` в JSON или пустую строку в multipart. Отсутствие `title_audio` сохраняет
аудио; для удаления есть отдельный DELETE. Отсутствие `files` сохраняет основные
вложения, непустой список `files` заменяет их все — прежнее поведение.

## Создание и обновление

`POST /api/v1/auth/notes` → **201**, `PUT /api/v1/auth/notes/{id}` → **200**.
Оба требуют `Authorization: Bearer <access_token>`.

```json
{
  "note_type": "calendar",
  "note_date": "2028-02-29",
  "title": "День рождения",
  "lifecycle": "recurring",
  "recurrence_rule": "FREQ=YEARLY"
}
```

Для аудио используйте multipart: те же текстовые поля, отдельный файл
`title_audio`, при необходимости обычные файлы под повторяющимся именем `files`.
Файл аудио хранится как AAC/M4A в `note-title-audio/{noteId}.m4a` внутри
`NOTE_FILES_PATH`; используйте выданный URL, не собирайте путь вручную.
После PUT обновляйте локальную запись **ответом сервера**.
Для скачивания `title_audio_url` из авторизованного ответа заметки передавайте
пользовательский Bearer JWT. В публичном shared-ответе аудио имеет signed URL
и скачивается без JWT. Основные старые URL файлов сохраняют прежнее поведение.

При `one_time → recurring` передайте правило; при `recurring → one_time`
правило очищается автоматически. Обе смены сбрасывают `is_completed=false`.
Изменение `note_date` также сбрасывает завершение; следующая ежедневная проверка
заново завершит заметку, если её дата уже прошла.

`DELETE /api/v1/auth/notes/{id}/title-audio` → **200** с обновлённой заметкой.
Сохраняет текст, основные вложения, дату и повторение; повторный вызов допустим.

## Календарь и история

- `GET /api/v1/auth/notes?from=2029-02-01&to=2029-02-28&fields=meta` — метаданные,
  без `userId` и URL файлов. Загружайте страницы до `has_more=false`.
- Для recurring стройте бейджи по `occurrences`, а не по исходному `note_date`.
  Например, исходная дата `2028-02-29` даст occurrence `2029-02-28`.
- Для one_time стройте бейдж по `note_date`, скрывая его при `is_completed=true`.
  Завершённые записи остаются в ответах для архива и просмотра прошедшего дня.
- `GET /api/v1/auth/notes/by-date?date=2029-02-28` возвращает все записи дня,
  включая recurring из других лет; `occurrences` содержит выбранный день.
- Виртуальные даты не создают новые записи. ID, основные файлы и аудио-заголовок
  общие для всех повторений; `total` и пагинация считают **заметки**.
- При YEARLY 29 февраля переносится на 28 февраля невисокосного года; при
  MONTHLY 31-е переносится на последний день короткого месяца. Следующий месяц
  снова считается от исходного дня, без накопления сдвига.
- `GET /api/v1/auth/notes/{id}` возвращает полную запись. Список без параметров
  сохраняет прежние поля и добавляет новые; для календаря используйте диапазон.

Граница автозавершения — **UTC**, проверка при старте сервера и ежедневно в
**00:05 UTC**. `note_date` остаётся календарной датой: не преобразуйте её через
`toUtc()` перед отправкой. Flutter отвечает за локальные уведомления и UI.

## Поделиться и импортировать

1. Владелец вызывает `POST /api/v1/auth/notes/{id}/share`, JSON:
   `{"expires_in":168}`. Тело можно опустить; срок по умолчанию — 7 дней,
   допустимо 1–8760 часов.
2. Ответ **201**: `share_url`, `share_token` (12 символов), `expires_at` (UTC).
   `share_url` имеет формат `https://timeleak.kz/share/{token}`.
   Передавайте в системный share именно `share_url`.
3. `GET /share/{token}` — публичное HTML-превью с OG-тегами. Установленное
   приложение открывает HTTPS-ссылку через iOS Universal Links / Android App Links.
   Если ссылка открылась в браузере, страница перенаправляет iOS (включая iPad)
   в App Store, Android — в Google Play. На компьютере остаются превью и кнопки
   обоих магазинов. Кнопка `timeleak://note/{token}` доступна для ручного открытия.
   Старый маршрут `/s/{token}` продолжает работать.
4. Получатель вызывает **без JWT** `GET /api/v1/notes/shared/{token}`.
   Ответ: `id` оригинала, `title`, `note_type`, `note_date`, `note_files`,
   `file_sizes` (байты в том же порядке), `title_audio_url`, `lifecycle`,
   `recurrence_rule`, `is_completed`, маскированный `shared_by`, `expires_at`.
5. После подтверждения скачайте файлы и создайте **новую** заметку через
   авторизованный `POST /api/v1/auth/notes`, повторно загрузив вложения.
   Используйте ID из ответа POST, а не ID оригинала. Backend не сохраняет
   заметку автоматически при открытии ссылки.

Файлы в публичном JSON имеют signed URL со сроком до **15 минут**, но не позже
истечения share-ссылки. URL используйте целиком. Для обновления URL повторите
GET shared. Доступ к файлам и превью проверяет токен, подпись, срок и наличие
оригинала. Новая share-ссылка не отзывает старую. Удаление оригинала удаляет
все его share-токены и вложения.

## Ошибки

Тело ошибки: `{"error":"..."}`.

| Код | Действие Flutter |
| --- | --- |
| 400 | Проверить дату, длину title, lifecycle/правило, формат и длительность аудио. |
| 401 | Обновить access token через существующий refresh flow. |
| 403 | Неверная роль; для signed URL — неверная подпись или истёкший URL файла. |
| 404 | Заметка чужая/удалена либо share-токен неизвестен. |
| 410 | Share-ссылка истекла; показать соответствующее сообщение. |
| 413 | Аудио-заголовок больше 2 MiB. |
| 503 | На backend недоступен FFmpeg/ffprobe; повторить после восстановления сервера. |

## Universal Links и App Links

Backend отдаёт без авторизации и редиректов, с `Content-Type: application/json`:

- `https://timeleak.kz/.well-known/apple-app-site-association` —
  `appID=9YQXS629VS.kz.timeleak.project.app`, `paths=["/share/*"]`.
- `https://timeleak.kz/.well-known/assetlinks.json` —
  `package_name=kz.timeleak.project.app`, SHA256 из `ANDROID_SHA256_CERT_FINGERPRINTS`.

В `.env` задаются `PUBLIC_BASE_URL=https://timeleak.kz`, `APPLE_APP_ID`,
`APPLE_APP_STORE_ID=6762095094`, `ANDROID_PACKAGE_NAME`,
`ANDROID_SHA256_CERT_FINGERPRINTS`. Несколько SHA256 (например, при смене
сертификата) разделяются запятыми. Для сборок из Google Play используйте SHA256
сертификата **App signing**, которым подписана установленная сборка.

На iOS добавьте Associated Domains: `applinks:timeleak.kz`; на Android —
`intent-filter` с `autoVerify=true`, `scheme=https`, `host=timeleak.kz`,
`pathPrefix=/share/`. Flutter должен извлекать токен из `/share/{token}` и
запрашивать публичный shared API из шага 4. URI `timeleak://note/{token}`
остаётся совместимым со старыми клиентами. После установки из магазина
пользователь должен повторно открыть исходную share-ссылку.

При аудите карточка Google Play для указанного package name отвечала 404;
до Android-релиза проверьте публикацию и доступность приложения в магазине.

Полный справочник схем, примеров, параметров и административных методов —
в `/swagger.json`. UI, исправления Flutter-плеера/записи и платформенные
настройки приложения выполняются в Flutter-проекте.
